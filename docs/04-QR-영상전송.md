# QR 연동 + 실시간 영상 전송

[01-기획](01-기획.md)의 2단계(QR 연동)와 3단계(실시간 영상)를 구현한 것과, 직접 돌려 본 방법을 정리한 문서.
기획의 미정 사항 "영상 전송 방식 (WebSocket vs WebRTC)"에는 **WebSocket + JPEG 프레임**으로 답한다.

## 한눈에 보기

```
PC 화면(/pair)                       api (FastAPI)                       폰(/m?sid=...)
 ① POST /api/session  ───────────▶  세션 발급 (sid)
 ② sid 로 QR 코드 표시
 ③ WS /api/ws/dash/{sid}  ◀──────▶  상태 푸시                     QR 스캔 → /m?sid=... 열림
                                                                   ④ 카메라 켜고 0.5초마다 JPEG 한 장
                                    ◀── WS /api/ws/phone/{sid} ───  프레임 전송
 ⑤ "● 연결됨", 받은 프레임 수,       frame_queue 에 보관
    최근 프레임 미리보기             (OCR 담당이 여기서 꺼내 간다)
```

- 폰은 영상 파일이 아니라 **사진을 연속으로** 보낸다. OCR 은 사진 한 장씩 읽으므로 WebRTC 같은 영상 스트리밍은 필요 없다.
- 세션은 추측하기 어려운 8글자 랜덤 값이고 30분 뒤 만료된다. 같은 세션에 폰이 또 붙으면 **새 폰이 이전 폰을 대체**한다.

## 어디에 뭐가 있나

| 위치 | 내용 |
| --- | --- |
| `services/api/app/main.py` | 세션 발급, 폰/대시보드 WebSocket, 최근 프레임 조회 |
| `services/api/app/sessions.py` | 세션 저장·만료·상태 |
| `services/api/app/frames.py` | **OCR 로 넘기는 지점** (`frame_queue`) |
| `services/api/tests/` | api 테스트 (`pytest`) |
| `src/components/QrPairing.js` | 대시보드 ① 패널 (QR + 연결 상태 + 프레임 미리보기) |
| `src/pages/PhoneCapture.js` | 폰 촬영 페이지 (`/m`). 맨 위 `CAPTURE_CONFIG` 에서 해상도·초당 장수 조절 |
| `src/pages/PairPage.js` | QR 만 단독으로 확인하는 페이지 (`/pair`) |
| `src/lib/api.js` | api 주소 만드는 도우미 |

대시보드가 완성되면 `<QrPairing />` 을 ① 패널 자리에 넣으면 된다. (`App.js` 는 건드리지 않았다)

## 주소 규칙 (api)

| 주소 | 용도 |
| --- | --- |
| `POST /api/session` | 세션 발급 → `{session_id, phone_path, expires_in}` |
| `WS /api/ws/phone/{sid}` | 폰 → 서버: 바이너리 JPEG. 서버 → 폰: `{"type":"ready"}`, `{"type":"stop"}` |
| `WS /api/ws/dash/{sid}` | 서버 → 대시보드: `{"type":"status","phone_connected":bool,"frames":n}` |
| `GET /api/session/{sid}/latest.jpg` | 가장 최근 프레임 (카메라 방향 확인용) |

폰 WebSocket 이 닫힐 때의 코드: `4404` 없는/만료된 세션, `4409` 다른 폰이 대체, `4410` 연결 중 만료.

## 프레임 규칙 (OCR 담당과 합의 필요)

`src/pages/PhoneCapture.js` 의 `CAPTURE_CONFIG`: 해상도 1280x720 요청, 초당 2장, JPEG 품질 0.8.
송신이 밀리면 프레임을 **버린다** (지연이 쌓이지 않게). 프레임 하나는 최대 2MB.

## 직접 돌려 보기

### A. PC 한 대에서 (폰 없이)

```bash
conda activate ocr-rag
cd services/api
uvicorn app.main:app --reload --port 8000     # 터미널 1: api

npm start                                      # 터미널 2 (레포 루트): http://localhost:3000/pair
```

`npm start` 는 `.env.development` 덕분에 api(`localhost:8000`)에 바로 접속한다.
`/pair` 에서 QR 이 뜨면 정상이다.

### B. 폰으로 (카메라는 https 에서만 켜진다)

프론트를 빌드하면 api 가 같은 주소로 함께 서빙한다. 그래서 **터널 하나**만 열면 된다.

```bash
npm run build                                  # 레포 루트
cd services/api
uvicorn app.main:app --port 8000               # http://localhost:8000/pair 도 열림

cloudflared tunnel --url http://localhost:8000 # 다른 터미널. https://....trycloudflare.com 이 나온다
```

1. PC 브라우저에서 **터널 주소**의 `/pair` 를 연다. (`localhost` 로 열면 QR 이 폰에서 못 여는 주소가 된다)
2. 폰으로 QR 을 스캔 → "카메라 켜고 전송 시작" 버튼 → 권한 허용.
3. PC 화면이 "● 연결됨"으로 바뀌고 받은 프레임 수와 미리보기가 나온다.
4. 끝나면 터널과 서버를 **꼭 종료**한다. 터널이 열려 있는 동안은 누구나 그 주소로 들어올 수 있다.

### 테스트

```bash
cd services/api && pytest          # api (4개)
npm test -- --watchAll=false       # 프론트 (App.test.js 는 CRA 기본 테스트라 원래 실패한다)
```

## 알아둘 점

- **개발 서버(`npm start`)의 proxy 로 WebSocket 을 보내면 개발 서버가 죽는다.** (Node 24 / Windows 에서 `ECONNRESET` 으로 확인) 그래서 proxy 대신 `REACT_APP_API_ORIGIN` 으로 api 에 직접 접속하고, 폰 테스트는 빌드본을 api 가 서빙한다.
- 폰의 **화면 자동 회전을 꺼 두면** 가로로 들어도 사진이 90도 누워서 온다. 자동 회전을 켜고 페이지를 새로고침한다.
- 손으로 들면 흔들려서 글자가 번진다. **거치대에 고정**한다.
- 컨베이어 카드가 **9:16 세로형**이라 폰을 가로·세로 중 어느 쪽으로 찍는 게 OCR 에 유리한지는 아직 비교 전이다.
