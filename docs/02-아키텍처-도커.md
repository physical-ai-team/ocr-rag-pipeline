# 아키텍처: Docker 컨테이너 구성 (초안)

## Docker를 왜 쓰나 (처음 보는 사람용)

- **컨테이너** = 프로그램 + 그 프로그램이 돌아가는 데 필요한 환경(Python 버전, 라이브러리 등)을 통째로 담은 상자.
- 누구 PC에서 실행하든 상자 안 환경은 똑같다 → "내 PC에선 되는데?" 문제가 사라진다.
- **기능별로 나눈다** = OCR 상자, 임베딩 상자, DB 상자… 처럼 기능마다 따로 컨테이너를 만든다.
  - 한 기능이 죽어도 나머지는 산다.
  - 팀원별로 맡은 컨테이너만 작업하면 돼서 서로 충돌이 적다.
  - OCR처럼 무거운 라이브러리가 다른 기능의 환경을 오염시키지 않는다.
- **docker compose** = 여러 컨테이너를 한 번에 켜고 끄는 도구. `docker compose up` 한 줄로 전체 시스템이 뜬다.

> conda 가상환경(`environment.yml`)은 각자 PC에서 코드 작성·테스트할 때 쓰고,
> Docker는 전체 시스템을 합쳐서 실행할 때 쓴다고 생각하면 된다.

## 컨테이너 구성안

| 컨테이너 | 하는 일 | 담당 단계 | 기술 후보 |
| --- | --- | --- | --- |
| `frontend` | 대시보드 웹페이지 (원문 컨베이어, QR, 저장 현황, RAG 검색), 휴대폰 촬영 페이지 | 1, 2, 6 화면 | React (현재 레포 루트) |
| `api` | QR 세션 발급/페어링, 휴대폰 프레임 수신(WebSocket), 저장 현황 실시간 푸시, RAG 검색 API | 2, 3, 6 | FastAPI |
| `ocr` | 프레임 이미지 → 영어 텍스트 | 4 | PaddleOCR / EasyOCR |
| `embedding` | 텍스트 → 벡터, Vector DB 저장 | 5 | sentence-transformers |
| `vectordb` | 벡터 저장·유사도 검색 | 5, 6 | Qdrant / Chroma |

```
 휴대폰 ──frames(WebSocket)──▶ api ──이미지──▶ ocr ──텍스트──▶ embedding ──벡터──▶ vectordb
                                 ▲                                                    │
 frontend ◀──저장 현황(WebSocket)─┤                                                    │
 frontend ──질문──▶ api ─────────────────────────── 유사도 검색 ──────────────────────▶┘
                     └──▶ LLM 답변 생성 ──▶ frontend
```

## 폴더 구조 (예정)

```
ocr-rag-pipeline/
├── src/, public/          # frontend (현재 위치 유지)
├── services/
│   ├── api/               # Dockerfile, app/
│   ├── ocr/               # Dockerfile, app/
│   └── embedding/         # Dockerfile, app/
├── docker-compose.yml     # 전체 컨테이너 정의
├── environment.yml        # 로컬 개발용 conda 환경
└── docs/
```
