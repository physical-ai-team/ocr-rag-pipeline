# 기획: OCR 및 벡터 임베딩 기반 영문 텍스트 데이터 추출·검색 파이프라인

## 한 줄 요약

PC 웹페이지에 흘러가는 영어 원문을 **휴대폰 카메라로 실시간 촬영**해 텍스트로 추출(OCR)하고,
**임베딩 벡터로 Vector DB에 저장**한 뒤, **질문으로 검색(RAG)** 하는 시스템.

```
[PC 웹페이지]  →  [휴대폰 카메라]  ─frames→  [서버: OCR → Embedding]  →  [Vector DB]
 영어 원문 송출      실시간 촬영                  추출 · 벡터화                  저장 · RAG 검색
```

## 전체 흐름 6단계

| # | 단계 | 내용 | 구분 |
| --- | --- | --- | --- |
| 1 | 웹페이지 열기 | 원문 컨베이어 + 대시보드 | 수집 (Capture) |
| 2 | QR 연동 | 웹페이지 ↔ 휴대폰 세션 페어링 | 수집 (Capture) |
| 3 | 실시간 영상 | 휴대폰 → 서버로 프레임 전송 | 수집 (Capture) |
| 4 | OCR | 프레임 → 텍스트 | 처리·적재 (Process) |
| 5 | 임베딩 + DB 저장 | 텍스트 → 벡터 → Vector DB | 처리·적재 (Process) |
| 6 | 현황 + RAG 검색 | 실시간 저장 현황 표시, 질의응답 | 활용 (Serve) |

## 반드시 구현해야 할 기능

1. **QR 연동**: 웹페이지와 휴대폰을 QR 코드로 연결
2. **실시간 영상 전송**: 휴대폰 카메라 영상을 실시간으로 서버에 전달
3. **OCR**: 영상 속 영어 원문을 텍스트로 추출
4. **임베딩·DB 저장**: 추출 텍스트와 임베딩 벡터를 DB에 저장
5. **실시간 저장 현황**: 저장되는 현황을 웹페이지에 실시간 표시
6. **RAG 검색**: 저장된 내용을 바탕으로 질문에 답변

## 웹페이지에 반드시 있어야 할 3가지 (대시보드)

| 패널 | 내용 |
| --- | --- |
| ① QR 카메라 연동 | QR 코드 표시 → 휴대폰으로 스캔 → 카메라 연결 상태(연결됨) 표시 |
| ② 실시간 저장 현황 | `11 / 100 저장` 같은 진행률 + 저장된 문서 목록(번호, 제목, 저장됨) — LIVE 갱신 |
| ③ RAG 검색 | 질문 입력창 + 검색 버튼 → 저장된 원문 기반 답변 |

추가로 화면 한쪽에 **원문 컨베이어**(OCR 대상 영어 문서들이 흘러가는 영역)가 있어야 한다.

## 미정 사항 (팀 논의 필요)

- [ ] OCR 엔진 (예: PaddleOCR, EasyOCR, Tesseract, 클라우드 OCR API)
- [ ] 임베딩 모델 (예: sentence-transformers, OpenAI/Claude 계열 API)
- [ ] Vector DB (예: Qdrant, Chroma, pgvector)
- [ ] RAG 답변용 LLM
- [ ] 백엔드 프레임워크 (예: FastAPI)
- [ ] 영상 전송 방식 (WebSocket으로 프레임 전송 vs WebRTC)
- [ ] 같은 원문이 여러 프레임에 찍혔을 때 중복 저장 방지 방법
